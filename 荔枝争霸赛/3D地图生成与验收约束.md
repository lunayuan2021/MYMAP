# 3D 地图生成与验收约束

## 1. 适用范围

本文档适用于荔枝争霸赛所有 3D 地图，包括当前第一个 Demo 地图以及后续新增地图。生成、导入、摆放和验收时必须执行同一套规则，不允许只凭俯视图判断正确。

所有尺寸均以 Unity 世界单位计，默认 `1 unit = 1 m`。地图对象必须使用统一坐标系：`Y` 为竖直方向，模型底面朝下，正面朝向道路或主要观察方向。

## 2. 强制生成顺序

1. 生成连续地形和基础高度。
2. 生成道路中心线、道路面和路肩。
3. 生成河道轮廓，并对地形进行真实下挖。
4. 创建水面和河床，不得直接在完整土地上覆盖透明水片。
5. 放置建筑节点，并按建筑语义分别贴地或入水。
6. 放置山体、岩石和悬崖，并执行道路净空检测。
7. 放置树木、灌木、草和花，并执行河道与道路排除检测。
8. 放置中文标签和交互标记。
9. 执行顶视、正视、右视、等距视角和近景验收。

不得在地形、道路和河道尚未定型时批量散布建筑、山体或植被。

## 3. 地形规则

- 地形必须是连续网格，不允许相邻区块出现可见裂缝、悬空边或重叠闪烁。
- 地形网格分辨率必须满足细节要求：河道及岸坡走廊内的格距不得大于河道全宽的 `1/6`（当前 Demo 河道全宽 `3.15`，对应上限 `0.5`，实际使用 `0.4`）。格距过粗会让下挖呈台阶状，导致河岸与陆地出现可见"断节"。
- 允许全图统一细格距，也允许仅在河道走廊内加密，但同一网格内不得出现 T 形接缝。
- 建筑、道路、山体和植被所使用的地面高度必须来自最终地形碰撞面，不得使用预估高度。
- 地形修改后必须同步更新 `MeshCollider.sharedMesh`。
- 地形高度发生任何修改（重建、节点基台、码头平台、河道下挖）后，所有道路网格必须逐顶点重新贴合：`y_new = H_new(x,z) + (y_old − H_orig(x,z))`，保留原设计净高；线带、箭头等叠加层按贴合后的道路重建。禁止让静态道路网格停留在旧地形高度上（会被新地形掩埋或悬空）。
- 节点基台：压平半径 = 建筑包围盒半径 × 0.8 + 0.3（上限 3.6），高度取**原始地形**在锚点处的高程；临水节点基台不得低于水面 +0.10。禁止在已修改地形上二次叠加基台（会形成坑壁）。
- 地形坡度突变处必须有过渡带，禁止形成垂直薄墙或小面积尖刺。
- 河道、道路完成后，不得再次用旧地形资源覆盖最终地形。

## 4. 水面与河道规则

### 4.1 水面

- 水面必须是无厚度的顶面网格，不得使用带垂直侧壁的透明盒子。
- 水线高度不得采样水面投影范围内、已被河道下挖的地形顶点。
- 每个横截面必须在左右水边外侧 `1.50-2.00` 处采样最终可见岸口，以较低一侧为控制岸。
- 水面高度必须比控制岸低 `0.08-0.12`；当前 Demo 使用 `0.10`。
- 同一河段的横截面必须保持同高；纵向允许随地形缓慢下降。
- 水面纵向坡度不得超过 `0.02 / 单位长度`（当前 Demo 上限值）。陡坡水面是"水面悬空盖物/切建筑"的直接根源：倾斜水面平面在弯道和邻近物体处必然穿帮。原始地形落差大时，应压平水位并把河道挖成浅峡谷，而不是让水面跟随地形陡降。
- 岸线强制必须使用"采样点半径 2.6 内的最高水位"，不得只取最近中心线点的水位（弯道处最近点会低估邻近水位）。
- 水面材质必须使用 URP 兼容 Shader，不得出现粉色材质、纯白高亮条或不透明蓝色块。
- 全图任何非河床区域的最终地表不得低于邻近水面：岸线强制 `地表 ≥ 水面 + 0.08`（路基浅滩与码头平台除外）。岸线强制必须在所有基台/平台修改之后执行，否则会出现"水面高于陆地/水面悬空盖物"。
- 岸线强制的作用范围必须覆盖**整个近河区域**而不是只有岸坡：距河道中心线 `10` 以内全强制，`10-16` 渐隐回原地形。教训：河湾内侧"半岛"低地距两条河都超过岸坡范围，原始地形低于水位时，从低角度看水面边缘悬空、树木从远处水面里穿出。
- 多条水道的交汇点和河道端头必须放置圆形水面补丁（半径 ≈ 水面半宽 + 0.1），覆盖两条水带之间的楔形缝隙。
- **水面板边缘必须被岸坡掩埋**：地形穿过水位线的位置必须在水面网格半宽**内侧**（当前 Demo：水面半宽 1.575，地形在 1.35-1.50 间从水下 0.04 升到水上 0.06）。若地形在水面边缘之外才升出水面，水板边缘会沿全河道悬浮可见。
- 区域低地填充不得豁免路基：填充统一执行，再由"道路逐顶点贴合"把路面抬到新地形之上，否则道路会陷在两侧抬高的地沟里被遮挡。
- 透明水材质必须使用 `ZTest LEqual`，并通过 `ZWrite On` 或独立深度预通过保证前景建筑、码头和船体能正确遮挡水面。
- 禁止仅依据 Transform、Bounds 或数值日志判断水线，必须从贴近地面的正视/侧视近景进行视觉验收。

### 4.2 河床与岸坡

- 水面下必须存在可见河床，不能让原土地表继续穿过水面。
- 常规河床深度为 `0.60-1.00`；当前 Demo 使用 `0.72`。
- 岸坡过渡宽度为 `1.20-1.80`，从岸口平滑下降到河床。
- 岸坡由最终地形本身形成，禁止再叠加浮空的河岸壳体。
- 河床材质应比岸边更暗、粗糙度更高，避免看起来像普通草地。
- 河床与水面之间不得发生 Z-Fighting。
- 推荐实现方式：河床不使用独立贴片网格，而是把地形网格按三角形拆分为"草地/砂石"两个子网格（SubMesh），砂石子网格覆盖河床和岸坡（距中心线 `< 水面半宽 + 0.4` 且顶点高度 `< 水面 + 0.12` 的三角形）。这样河床与岸坡天然连续，不会产生贴片缝隙或 Z-Fighting。
- 砂石带必须延伸到水面以上 `0.3-0.6` 形成可见岸滩，再过渡为草地，避免水草直接交界。
- 道路与河道相接处（路基水平 `1.0` 范围内）河床应抬升为浅滩，最小水深 `0.16`，防止路面端头悬空。

### 4.3 河道自动验收

- 每个水面横截面都要分别采样左右岸外侧高度，禁止使用河道中心或水面正下方的地形高度。
- `水面高度 - 较低控制岸高度` 必须在 `[-0.12, -0.08]`。
- 同一横截面左右水面顶点高度差必须小于 `0.01`。
- `水面高度 - 河床高度` 必须在 `[0.60, 1.00]`。
- 河道范围内不得保留普通草、花、灌木或树干。
- 允许专用芦苇、水草和湿地植物，但必须使用单独的水生植被标签。
- 近景中前景建筑不得被后方透明水面覆盖；发现覆盖时必须检查 Shader 深度测试与渲染队列，不能只继续移动模型。

## 5. 水驿、码头和船只规则

水上建筑节点必须采用语义化层级，不得把船、码头、房屋合并为一个无法单独调整的超大网格。

推荐 Prefab 层级：

```text
WaterStation
├── House_OnLand
├── Dock_AboveWater
├── Piles_IntoWater
├── Boat_OnWater
├── Props
└── LabelAnchor
```

### 5.1 船

- 船体最低点应低于水面 `0.08-0.18`，形成合理吃水。
- 甲板和船舱主体必须高于水面。
- 船不得整体沉入水中，也不得完全悬在水面上方。

### 5.2 码头

- 码头平台顶面必须高于水面 `0.08-0.20`。
- 桩柱可以穿过水面并延伸至河床。
- 码头与岸边连接处不得出现断层、悬空或被岸坡掩埋。

### 5.3 房屋

- 房屋主体必须位于岸上，其地基与最终地形接触。
- 地基允许压入地形 `0.02-0.08`，不得悬空。
- 房屋墙体、门和台阶不得被水面覆盖。
- 房屋与水面的水平距离应符合建筑语义，不得把普通驿站放在河中央。

### 5.4 水驿模型导入要求

- 船、码头、房屋必须是独立子对象或独立网格。
- 禁止使用接近百万顶点、包含数千离散连通块的单一合并网格作为最终节点。
- 每个语义部件必须有独立 Pivot，便于按水线和地形调整。
- 导入后必须检查 GLB/FBX 坐标轴，确保底面朝下而不是侧立。
- 若临时素材仍是单一合并网格，不得用整体 Bounds 最低点直接确定吃水；必须结合顶点高度分布、近景遮挡和实际船体/平台位置复核。

### 5.5 单一合并网格的临时处置流程

正式做法永远是拆分部件；在素材尚未拆分前，按以下流程兜底：

1. **判定船向**：在世界空间对模型顶点做 XZ 网格化高度分簇——相对高度 `≥0.60` 且占顶点多的格子为"房屋簇"，相对高度 `≤0.30` 的低矮格子质心为"船/栈桥端"。船向 = 房屋簇质心 → 低簇质心。
2. **旋转**：使船向垂直指向河道中心线（取最近河段切线的水平法线，房屋保持在原岸侧），偏差小于 `8°` 时不动。
3. **平移**：使低簇质心位于距中心线约 `0.35` 处（船体覆盖水面），并校验房屋簇质心距中心线 `≥2.0`，否则人工复查。
4. **码头平台**：在房屋质心周围把地形压成低岸平台（内半径约 `1.9` 压至 `水面+0.03`，外沿 `3.4` 余弦过渡；只降不升，不得在河道内形成堤坝）。
5. **基座折中**：模型底面统一置于 `水面 - 0.08`（船获得最小吃水），房基入土约 `0.11`，超出 `0.02-0.08` 的常规区间属于已知折中，必须记入 `Validation`。

## 6. 普通建筑节点规则

- 建筑底面与地形间隙不得超过 `0.03`。
- 建筑地基压入地形范围为 `0.02-0.08`。
- 建筑中心不得侵入道路有效行驶面。
- 建筑正面应朝向道路、广场或主要镜头，禁止背门朝路。
- 建筑尺寸必须与节点密度匹配：目标足印（XZ 较大边）= `clamp(0.62 × 最近邻锚点距离, 1.7, 3.4)`。现尺寸偏离目标 `±5%/+30%` 以外时按比例缩放，禁止相邻节点建筑包围盒互相穿插。
- 起点/终点地标例外：终点宫城可放大至 7.0 级别；与之相邻的宫门节点（GATE）作为宫城前门组合，宫门模型可沿道路轴线向来向前移 ≤ 2.0 至宫墙面前，标签随模型移动（锚点逻辑坐标不变）。
- 建筑正面判定：用"高殿簇→低台阶簇"的顶点高度聚类方向作为正面（台阶/前院在低簇侧），正面必须朝向道路来向；GATE 类门洞轴线必须与道路轴线对齐。
- 缩放后必须重新贴地并按新 Bounds 重算标签高度。
- 占位平台和信标在正式模型启用后必须关闭。
- 建筑标签应位于最高点上方 `0.60-1.00`，不得穿过屋顶。

## 7. 山体与岩石规则

- 主山体优先使用 `Hill Rock Mountain Terrain` 素材包。
- 所有材质必须转换为 `Universal Render Pipeline/Lit` 并保留 Albedo、Normal、Metallic/Smoothness 和 AO。
- 山体模型的平坦方形底座必须裁除或隐藏，不能看到 Terrain Patch 边界。
- 山体底部至少 `80%` 的采样点应与地形接触。
- 山体底部最大悬空间隙不得超过 `0.05`。
- 山体允许压入地形 `0.03-0.12`，但不能出现明显下垂裙边。
- 山体不得使用统一缩放和统一旋转，应有合理的尺度和朝向变化。
- 大型山体必须配置 LOD 或视距裁剪；碰撞体应使用简化网格。

### 7.1 道路净空

- 山体、岩石和树干距离道路可行驶边缘至少 `0.60`。
- 任何山体网格不得覆盖道路顶面。
- 山体跨越道路时必须使用专门的隧道、桥洞或栈道结构，不能直接穿模。
- 自动检测应使用道路网格三角形，而不是只比较对象中心距离。

## 8. 道路规则

- 普通道路顶面应高于最终地形 `0.04-0.10`。
- 山路顶面应高于最终地形 `0.07-0.12`。
- 当前 Demo 山路平均净高为 `0.095`。
- 道路不得整体陷入地形，也不得像桥一样悬空。
- 路肩必须与周围地形平滑过渡。
- 道路转弯、交叉口和节点入口不得被草、岩石、山体或建筑挡住。
- 道路材质不得与地形完全同色，应保持清晰但不过度发亮。

## 9. 植被规则

- 普通草、花、灌木和树干不得位于河道水面投影范围内。
- 树冠可以自然伸到河面上方，但树干必须位于岸上。
- 树干距离水边至少 `0.35`，大型树至少 `0.60`。
- 普通草距离水边至少 `0.15`；水生植物除外。
- 树干和大型岩石距离道路边缘至少 `0.60`。
- 草和花距离道路边缘至少 `0.15`，不得长在行驶面中央。
- 同类树木树干间最小间距 `2.1`（按树冠尺度可上调），禁止树冠明显穿插；节点周边可用迭代松弛（互斥推开 + 河道/建筑净空约束 + 重新贴地）自动满足。
- 树干与节点建筑包围盒边缘至少保持 `0.8`。
- 植被移动后必须重新向最终地形做射线贴地。
- 禁止在同一点重复生成多组 LOD Prefab。

## 10. 标签与远距离可读性

- 中文节点名称必须在默认远景镜头中可读。
- 标签不得被树冠、山体或屋顶遮挡。
- 标签应使用粗体、描边或阴影，并始终朝向主要镜头。
- 标签高度根据建筑最终 Bounds 计算，不使用固定世界高度。
- 标签不得投射到水下或地形内部。

## 11. 命名与层级约束

推荐地图根节点结构：

```text
MAP_ROOT
├── Terrain
├── Routes
│   ├── OfficialRoad
│   ├── MountainRoute
│   └── WaterRoute_And_River
├── Node_Anchors
├── Natural_Decoration
│   ├── Mountains
│   ├── Rocks
│   ├── Trees
│   └── Groundcover
├── WaterStations
└── Validation
```

- 节点锚点统一命名为 `Sxx_ANCHOR_中文名`。
- 水面使用 `Exx_Route`，河床使用 `Exx_RiverBed`。
- 修复和生成批次必须带日期或版本后缀，避免覆盖来源不明。
- 正式场景中只允许一个有效地形、一个有效水面和一个有效河床版本。
- 修复必须从源头资产入手（重建地形/网格/材质），禁止在问题表面叠加新的贴片对象（如 `VisibleRiverBed`、`RiverBank` 壳体）。每次修复落地后必须删除被替代的旧补丁对象和旧版本网格引用，场景中不得残留禁用状态的历史补丁。
- 原始未加工资产（如未下挖地形）必须永久保留，作为后续重建的唯一干净来源。

## 12. 自动验收清单

每张地图交付前必须通过以下检查：

- 水面与岸口高度差检查。
- 岸线高于水面检查（全图非河床地表 ≥ 邻近水面）。
- 地形修改后道路逐顶点贴合检查（道路不得被地形掩埋或悬空）。
- 水深和岸坡宽度检查。
- 水面下是否仍存在未下挖土地检查。
- 船、码头、房屋分别与水面和地形的关系检查。
- 建筑底面悬空和穿地检查。
- 山体底部多点悬空检查。
- 山体与道路三角形相交检查。
- 道路相对地形高度检查。
- 树木、草、花和岩石与河道相交检查。
- 树木同类间距与树冠穿插检查。
- 相邻节点建筑包围盒穿插检查。
- 场景中历史补丁对象残留检查（不得存在禁用的旧河床/河岸壳体）。
- 树木、岩石与道路净空检查。
- 标签远距离可读性和遮挡检查。
- URP 材质、丢失贴图和粉色 Shader 检查。
- Unity Console Error 和 Exception 检查。

## 13. 视角验收要求

每次修改后至少输出以下视角：

1. 全图等距视角：检查整体比例和节点分布。
2. 顶视图：检查道路、河道、建筑和山体平面相交。
3. 正视图：检查悬空、穿地、水深和建筑高度。
4. 右视图：检查另一方向的悬空和坡度。
5. 水驿近景：检查船、码头、房屋和水线。
6. 山路近景：检查道路净空、山体接地和植被遮挡。

只通过顶视图不算验收完成。
