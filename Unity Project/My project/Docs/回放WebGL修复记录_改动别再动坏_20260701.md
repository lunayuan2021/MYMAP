## 二、⭐ WebGL 和 Play View「两套东西」的最大来源：LycheeWebGLImageSpriteGuard

这是「修这块坏那块、两边不一致」的核心。`LycheeWebGLImageSpriteGuard`（`#if UNITY_WEBGL && !UNITY_EDITOR`）每帧 `FindObjectsByType<Image>` 把**所有** UI Image 换成 RawImage 代理、清掉原 Image 的 sprite。后果：
- Play View 走正常 Image 路径，WebGL 走「全换 RawImage」路径 → **两套渲染**，很多 bug 只在包里犯（头像空棕圆就是它把 Mask 图形也清了）。
- RawImage 不支持九宫格 border / fillAmount / 逐 Image 材质 → WebGL 保真度下降。
- 每帧全场扫描 → 性能负担（旧版日志刷到 3000+）。

它当初是为绕**结算页**一个硬崩（播到最后出结算那一下整页 `null function` WASM trap）加的。但那崩溃的真根因（据 `Docs/交接_回放WebGL修复_20260630.md` 主假设）是**结算背景的 `RectMask2D`(`LycheeSettlementScreen.cs`)** 触发未预热的裁剪 shader 变体，不是 Image secondary texture（本工程没有任何带 secondary texture 的 sprite）。

**这轮的收敛动作（✅ 已在真 WebGL 包 092316 验证：opening→537 回合→结算页全程零报错，结算「blue-l4 夺魁」页正常出，就是那个崩溃住的地方）：**
- `LycheeWebGLImageSpriteGuard.GuardEnabled=false` → 不挂 guard，WebGL UI 走和 Play View 一样的 Image 路径（九宫格边框/材质恢复保真、去掉每帧全场扫描）。
- `LycheeSettlementScreen.cs` WebGL 下不加结算背景 `RectMask2D` → 根治那个裁剪 shader 变体硬崩（超出屏幕的底图本就在屏幕外，视觉无差）。**验证证明：guard 当初想兜的崩溃真根因就是这个 RectMask2D，不是 Image secondary texture，去掉它就够了，guard 是多余的。**
- **回退开关（保留没删）**：万一日后某张图/某局在 WebGL 结算又硬崩，把 `GuardEnabled` 改回 `true` 即整体恢复旧兜底（代价=重新丢九宫格保真度 + 每帧扫描）。guard 文件和 mask-skip 补丁都留着当保险，别删。
- 顺带：这个 guard-off 包同时验证了 Issue 2(头像)、Issue 3(中央出牌窗)、Issue 7(红队完成红底)在 WebGL 都正常。

> 注意：`minimap` 那个 `RenderPipeline.SubmitRenderRequest` 硬崩是**另一个**、开场就崩的独立问题，已在 `LycheeMinimapSystem.cs` 用「WebGL 保持相机 enabled、走 URP 常规渲染」修好，**和 guard 无关，别去动小地图那段**。

## 四、WebGL 音频「一定要点一下」是浏览器规矩，不是包的毛病

- **零点击出声在现代浏览器不可能**：Unity WebGL 走 Web Audio，AudioContext 默认 `suspended`，必须一次真实用户手势(pointerdown/touchstart/keydown)后 `resume()` 才 `running`。Chrome/Safari/Firefox 都一样。
- **任意一处的第一次点击/触摸/按键都能解锁**：`index.html`(~196 行)把 resume 监听挂在 `window` 上(不是某个按钮)，点画面/点加载页/按任意键都行；C# 端 `LycheeAudioDirector.TryResumeWebAudio` 每 0.4s 再补一次并把 BGM 踢到已恢复的 context。
- **唯一的体验缺口是「没提示要点」**：加载遮罩只说「Loading…」、~2.6s 自动消失，没说「点一下开声音」。可选改进：把遮罩文案改成「点击任意处开启声音」并留到首次交互再消失，或加个 click-to-start 全屏层（这属于 `LycheeWebGLBuild_20260612.cs` 的 `PatchIndexHtml`）。**这是可选 UX，不做也不影响功能**。

## 十三、20260702 外部干扰澄清：efficiency_tools 报错**不是本包的**——别追

**现象**：WebGL 页控制台报 `TypeError: Cannot read properties of null (reading '_eventTypes')`，调用栈 `jx.event.js → site.sidebar.js → site.nain.js`，来源标注 `efficiency_tools`。

**结论（已实锤，无需改任何代码）**：
- 我们的构建包里**只有一个 JS**（`Build/*.loader.js`）+ index.html 一段内联脚本；`jx.*.js` / `site.*.js` 任何构建包里都不存在（find 全包验证过）。
- 这是名为 **efficiency_tools（效率工具）的浏览器扩展**往页面注入的内容脚本在自己报错：它的侧边栏初始化(`site.sidebar.js init`)在我们的游戏页上找不到它预期的 DOM 元素（getElementById 返回 null），拿 null 去 `addEventListener` → 读 `_eventTypes` 崩。JX(jx.core/jx.event) 是腾讯系前端框架，游戏和 Unity 模板都不用它。
- **对游戏零影响**：扩展脚本崩在它自己的初始化里，不碰 Unity loader/canvas。若错误监控平台把它标成 "Impactful"，属于采集页面 console 的误报。

**验证/消除方法**（给测试同学）：无痕窗口（默认禁扩展）打开同一 URL → 该报错消失、游戏一切照旧；或 `chrome://extensions` 里禁用"效率工具/efficiency tools"类扩展。国产浏览器（360/搜狗等）自带的"工具栏/侧边栏"也可能是注入源，换 Chrome 干净配置即可分辨。
- 若在错误采集平台做过滤：按来源 `efficiency_tools` / 文件名 `jx.event.js|site.sidebar.js|site.nain.js` 加白名单忽略。

**别做的事**：别为这个报错去改 index.html/loader/游戏代码——它不来自我们；改了也不会消失（除非禁掉那个扩展）。
