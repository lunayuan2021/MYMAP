# 地图/道路生成约束系统 · 设计稿

> 目标：让未来 map2/3/4… **"配置一丢就自动出活"**，作者只做两件事——**写配置 + 读校验报告**，零场景手调。
> 现状痛点：四路型外观规则散在生成器 2648 行各处常量/switch；山路凸起/官道平整根本没实现；`_Route` 主路面材质从不按类型分配（克隆模板继承）；贴地脚本 RibbonRefit/StationLift 只能对母版手动跑；好不好全靠肉眼看。

---

## 0. 总纲：三层切分

每张地图配置切成三层，**作者只碰前两层**：

| 层 | 内容 | 谁产出 |
|---|---|---|
| **拓扑层**（必填） | grid + nodes(id/type/x,y) + edges(id/from/to/**routeType**) + routePaths(points) | 作者 |
| **玩法层**（可选） | roles / resources / processNodes / tasks（全以 nodeId 引用） | 作者 |
| **派生层**（禁填） | 路面宽/抬升/材质/彩带、河谷下挖/沙床/水面、**路点世界 Y** | **生成器查表 + 采样地形** |

一句话总纲：**作者说"哪条路是什么类型、从哪到哪、大致怎么拐"；生成器决定"这类路长什么样、贴多高"。** `routeType` 是连接两层的唯一旋钮。

> 结构上已经挡住"作者手填高度"：数据模型 `LycheeGridPoint` 只有 `{x,y}`，没有任何 Y/height 字段——第三维永远由运行时对 `heightSamples` 双线性采样得到。

## 支柱① RouteProfile 路型档案表

把散落常量收成**一张跨地图共用的表**（一处编辑，四张图通用）。载体用**共享 JSON** `Assets/LycheeMap15/Configs/road_profiles.json`（理由：全链已用 JsonUtility 读 JSON、零自定义 ScriptableObject；JSON 可文本编辑、可进 git diff），配 plain-class `LycheeRouteProfileSet`；生成器入口一次性读入，缺文件回退内置默认（保证旧行为不回归）。

**默认值＝现有真实数值**（搬入时逐字等值，不改观感）：

| type | surfaceWidth | surfaceLift | overlayWidth | roadbedWidth | **surfaceMaterial**（★现未赋） | terrainOp |
|---|---|---|---|---|---|---|
| 官道 ROAD | 1.65 | 0.026 | 0.34 | 3.0 | M_Config_OfficialRoad.mat | **flatten**（新）|
| 河道 WATER | 3.2 | 0.038 | 0.36 | — | M_Config_WaterRoute.mat | carve（已有）|
| 山路 MOUNTAIN | 1.28 | 0.032 | 0.32 | 2.35 | M_Config_MountainRoute.mat | **raise**（新）|
| 支路 BRANCH | 1.4 | 0.028 | 0.30 | 2.65 | M_Config_BranchRoute.mat | none |

每行还含：border/ruts 偏移、roadbedMaterial、overlay{enabled,material}、decoReach（清障半径）、terrainOp 参数。

**★核心缺口（材质不分的根因）**：`RebuildRibbonChildren` 重画 `_Route` 网格后**从不赋材质**（`ReplaceRibbon` 只换 mesh），克隆模板时 `_Route` 顶着被克隆那条路的材质——所以支路从官道模板克隆就一样。**修复点唯一**：重画 `_Route` 后 `mr.sharedMaterial = LoadMat(Profile(type).surfaceMaterial)`（水路除外，其 `_Route` 归 CarveRivers）。这就是"四类材质明显区别"的落点。

**彩带开关**：`overlay.enabled=false` 时 `BuildOverlayLine` 直接跳过——"去彩带"变成一个布尔。

## 支柱② 地形塑形 op + 不变量（免人工调的关键）

把"挖河/抬山/平官道/支路随地形"统一成**一个声明式 pass**：每条边按 `Profile(type).terrainOp` 产出 `targetY(x,z)`，对**地形 mesh 副本**和 **heightSamples** 用**同一个 TargetY 闭包写穿两份**（彻底消除"mesh 改了高度场没改"的漂移）。

**合成语义**（同一格点多条边贡献）：carve 取 **min**（河永远把地拉低）、raise 取 **max**（山永远把地抬高）、flatten 向**沿程平滑基准 lerp**（官道抹平）；固定顺序 **carve→raise→flatten**，节点调和在前。
- raise/flatten **复用现成的"回填抬地"骨架** `RestoreFormerRiverTerrain/Elevation`（它已经把"动地形+同步高度场+SmoothStep 横断面"做对了）。

**不变量（每条给可计算判据，verify 逐条算，违例报坐标而非靠人眼）**：
- **河道**：河床 `bedY ≤ waterY − 0.12`；水深 `∈[0.15, carveDepth]`；DOCK/WATER_STATION 端 `anchor.y ≥ waterY + 0.20`（不没楼）。
- **山路**：脊线抬升达标；**相邻 pathPoint 坡度 ≤ 0.5（防爬崖/瞬移）**——超限就自动降 raiseHeight 重算，触底才报"该段先天过陡，去调 routePath"；与相邻非山路边在共享节点 `|Δy| ≤ 0.10`。
- **官道**：沿程坡度 ≤ 0.18；平整残差 ≤ 0.06。
- **全局**：共享节点高度调和（同节点各边采得地面差 ≤ 0.10）；mesh↔grid 一致（抽样偏差 ≤ 0.05，专防行序写反）；**carve 与 raise 不得同点生效**（河山几何重叠＝配置错，拦截报 edgeId）。

## 支柱③ 配置契约 + 预生成 Lint

一个纯函数 `Lint(config, rawJson)`，在**克隆母版之前**跑（最重的一段之前拦错，改一行配置秒级拿到"第 N 条边连了不存在的节点"）。两档：**error 阻断**（聚合全部一次报全）、**warn 放行写报告**。

**关键 Lint 规则（共 ~25 条）**：

- 唯一/存在（error）：nodeId/edgeId/pathId 唯一；edge.from/to 存在且 ≠；edge↔routePath 经 pathId 双向 1:1。
- 类型语义（error）：type/routeType 合法；**水路边"至少一端"是 DOCK/WATER_STATION；山路边"至少一端"是 MOUNTAIN_NODE/PASS**。
- 坐标几何：节点在 grid 界内（error）；**路点首尾≈端节点坐标**（error，强不变量——小队"从当前节点出发"靠它）；路点 ≥2（error，否则生成器静默丢边）；相邻点距 ∈[0.8,12]（warn）；节点间距 ≥1.5（error）。
- 连通性（error）：并查集全图连通；start→各 terminal 可达（warn）。
- 引用完整性（error）：gameplay/resources 引用的 nodeId 必须存在（升级自现有 ValidateFlexibleConfig）。
- 禁填扫描（warn）：JSON 里出现 width/lift/height/z 等派生字段 → 提示"已被忽略"。

**两个反直觉、必须写进契约的点**：
1. 水/山语义是**"至少一端"不是"两端"**（现役 E19=水驿↔普通站、E20=普通站↔山口都合法）——误写成"两端"会把合法配置判死。
2. **`distance` 是玩法成本，与几何长度完全解耦**（实测 E14 折线 24.9 / distance 72）——**绝不校验 `distance≈路长`**。

## 支柱④ 后生成自动校验 + 一键/批量流水线

**Verify pass**（新 `LycheeMapVerify`，只读，逐项 PASS/FAIL 写报告，取代肉眼）：

| 检查 | 规则 |
|---|---|
| V1 路点贴地 | pathPoint 距路面/水面 dy 在 [−0.12, 0.12]（水路点容许略浮）|
| V2 站点贴地 | 站房底相对地表 embed 在合理区间，不悬空不埋 |
| V3 水面覆盖 | 每条水路边水面命中率 ≥95% |
| V4 站点没水 | 陆站足迹中心不被水面淹 |
| V5 路面不穿地 | 路面顶点 ≥ 地形面（豁免站房足迹/路河重叠的有意下沉）|
| V6 路上无残留 | 清障后路面无残留植被岩石 |
| V7 高度场一致 | heightSamples 与 mesh 抽样偏差 ≤0.10（专防行序写反）|
| V8 坡度 | 各类型相邻路点坡度在限内 |
| V9 子物体名 | PathPoint_NN 连号、EdgeObstacleSlot 在、E##_Line_* 归位 |
| V10 路面材质 | `_Route.sharedMaterial` 名匹配 routeType（材质修复的回归断言）|

**折叠贴地脚本（必须修的现状阻塞）**：RibbonRefit/StationLift 现在**硬编码母版场景** `LycheeReplayDemo.unity`、靠各自 `.done` 轮询，且生成器 L505 注释承诺的 `RunOnScene` 入口**根本不存在**。→ 给两者各加 `RunOnScene(scene)` 纯函数入口（对**副本**跑），由流水线在保存前自动按序调用。
另外它们用 `assetPath.Contains("RoadGroundFit")` 认路面，**对新生成的 `MapLayout_<key>/*_Route.asset` 失效**（路径里没这子串）→ 改成稳健判据（子物体名 `_Route` 结尾 + 父对象是 MapRouteEdge）。

**单图流水线顺序**：S1 ApplyLayout（塑形→道路→材质/彩带→挖河→水驿抬升→清障）→ S2 StationLift → S3 RibbonRefit → S4 Verify → S5 保存+报告+截图。
**批量**：一个 `.request` 给 map1–4 路径，逐张走 S1–S5，各出 `*_map{i}_report.txt` + 截图（带 mapKey 后缀防覆盖）。
**幂等**：定义在**视觉层**（同配置→同顶点高度→同指纹/同 PASS-FAIL）；字节/GUID 不保证（如实写进报告）。

## 必须守的硬不变量（贯穿全系统）

1. **子物体名/数量/位置绝不可由档案表改动**——`PathPoint_NN`/`EdgeObstacleSlot`/`E##_Route` 等被回放/事件/小队/关卡硬引用。档案表只动尺寸/材质/op 参数。
2. **任何 terrainOp 改地形必须同步写 `heightSamples`**（行序 north→south，`idx=z*(W+1)+x`，`wz=origin.y+(H−z)*cell`）——漏写或写反 → 信使/小队浮空、沉地或南北镜像。
3. **水路 `_Route` 必须留在 `WaterRoute_And_River` 容器、保持水面材质**——否则运行时河面三角缓存采不到，小队该划船却走路。
4. **RunOnScene 只对副本跑，绝不碰母版 `LycheeReplayDemo.unity`**。
5. **carve > flatten > raise 的合成优先级**——防抬山把河填平。
