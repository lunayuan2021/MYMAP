背景：观众端老电脑播放回放"特别特别卡"。五维并行审计出 38 条问题（高影响项全部对抗核实），本批落地零画质代价的七项。验证包：`Builds/LycheeReplay_WebGL_20260702_124439_Linux`，用户已验证通过。

## 改动清单

1. **构建设置**（`Assets/LycheeReplayDemo/Editor/LycheeWebGLBuild_20260612.cs` 覆写块）：
   - `exceptionSupport = ExplicitlyThrownExceptionsOnly`（原 FullWithStacktrace 是 20260630 排查崩溃临时开的，忘了退；再诊断时临时改回重出包）
   - `debugSymbolMode = External`（wasm 内嵌 17MB name 段外置为 `.symbols.json.unityweb`）
   - `stripEngineCode = true` + 新建 `Assets/link.xml` preserve `UnityEngine.PhysicsModule`（保 CreatePrimitive 碰撞体，代替以前整体关裁剪）
   - `managedStrippingLevel = Medium`（若出现反射缺类：降 Low 或 link.xml 补保留）
2. **小地图脉冲渲染**（`LycheeMinimapSystem.cs`）：WebGL 相机默认关，RenderLoop 每 0.6s 开一帧走正常 URP 循环（AOT 安全，不碰 SubmitRenderRequest/Camera.Render 两条崩溃路）。
3. **帧调度**（`LycheeFrameRatePacing.cs`）：WebGL 分支 `targetFrameRate = -1`。任何非 -1 值都会让 Unity 弃 rAF 改 setTimeout 排帧（原注释把因果写反了）；60 上限仅保留给原生包。
4. **阴影**：PP_Grass_15/11、PP_Sunflower_04、rock_set_01~04 共 7 个 prefab `m_CastShadows: 0`；管线构建覆写追加：级联 2→1、软阴影 High→Low、附加光渲染模式 Disabled、附加光阴影关。
5. **网格去 Read/Write**：GeneratedMeshes 下 748 个烘焙网格 `m_IsReadable: 0`（含 WaterStationSplit 六件 92MB）。水面网格（大小写不敏感匹配 water/river/route/junction）全部保留可读；`LycheeReplayPlayer.BuildWaterTriangleCache` 加了不可读网格跳过防御（误伤只降级不崩）。
6. **GLB 瘦身**：31 个 GLB 原地 weld → simplify --error 0.01 → 贴图 resize 512，磁盘 218MB→72MB，零失败。蒙皮/骨骼名/节点结构验证无损（Member 74,902→18,006 tris，站点 ~75k→~30k）。**完整备份：`Backups_ModelsGLB_20260702/`**。
7. **回滚路径**：代码/设置/prefab/网格改动全在 git 工作树可 checkout；GLB 从备份目录拷回即可。

## 踩过的坑（防复发）

- **大小写敏感排除模式误伤水面**：`Line_WATER`（大写）绕过 `*Water*` 排除被剥离，git 还原 61 个后又因 WaterStationSplit 文件夹名带 "Water" 把水驿建筑组误还原，需再单独剥离。教训：文件名过滤一律用大小写不敏感，且区分"路径含水"与"是水面网格"。
- **构建请求被旧编辑器程序集消费**：改完编辑器脚本立刻 touch request，第一次构建用的是旧编译的 RunBuild——PlayerSettings 全没生效（wasm 没变小、无 symbols 文件、"restored: 2 properties"），但 player 侧脚本与资产是新的（data 变小了）。构建过程本身完成了新程序集装载，**再触发一次即正常**。判定新代码是否生效的三信号：Build 目录出现 `.symbols.json`、wasm 大幅缩水、报告 restored 数 >2。
- 构建报告的 `errors: 29521` 是既有统计噪音（07-01 旧构建同数字），非本批引入。
