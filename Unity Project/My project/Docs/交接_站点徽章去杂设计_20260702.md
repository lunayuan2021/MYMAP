# 交接：站点徽章去杂（领任务/领资源"徽章太多太乱"）— 2026-07-02

## 问题
用户反馈：**领任务/领资源时一个站点上的徽章太多、太乱**。经确认，主犯是 **#1 长排资源图标**。

## 诊断（一个"有资源/有任务"站点被领取时同时叠的东西）
对照 `Assets/LycheeReplayDemo/Systems/LycheeWorldMarkerSystem.cs`：

| 元素 | 来源 | 数量 |
|---|---|---|
| **资源库存图标行** | `RefreshResourceMarkers`→`SyncResourceIcons`→`LayoutStationBadgeRow`（每帧，凡 `resourceVisible` 节点） | **每种资源一个图标**，最多 7（`ResourceOrder`：冰鉴/快马/短驿马/过所/官凭/情报/船权），横排、**原无上限** |
| 障碍徽章 | 同一行追加 | +1（最多 8 连排） |
| 任务金柱 / 悬赏柱 | `RefreshTaskPillars` / `RefreshBountyPillars` | 竖柱各 1 |
| 处理进度条 | `CreateProgressRing`（领任务中/领资源中 + N/M） | 1 |
| 世界事件脉冲 | `RESOURCE_CLAIM` 在 `LycheeReplayPlayer.ShouldShowWorldPulse` 白名单 → 冒"获得X"飘字 | 1 |

主犯 = 资源库存行"每种一个图标、全量常显、无上限"。

## 选定方案（用户拍板：A+B+D，封顶 **3**）
- **A 封顶+溢出角标**：资源图标最多显 `MaxResourceIconsShown = 3`，多出的收成 **"+K"** 角标。**已盖章(刚领到，`resultMarked`)的优先占名额**，别把刚领到的藏进溢出。
- **B 领取时收起静态行 + 去冗余脉冲**：该站点有**活动进度条**（正在领取/处理）时，整条资源图标行收起（进度条已表达"在干嘛"）；同时 **`RESOURCE_CLAIM` 不再冒世界脉冲**（与资源行+左侧事件流+进度条重复）。
- **D 视觉收紧**：`StationBadgeSlotSpacing` 1.92 → **1.35**。

结果：一站点资源图标从最多 8 连排 → **最多 3 图标 + "+K" + 障碍**，领取瞬间只剩进度条（+障碍），画面干净。

## 改动点（都带 `方案A/B/D` 注释，别改回"全量常显"）
`Assets/LycheeReplayDemo/Systems/LycheeWorldMarkerSystem.cs`
- 常量：`StationBadgeSlotSpacing=1.35`(D)、新增 `MaxResourceIconsShown=3`(A)。
- `ResourceMarker.overflowChip`(A)、`ProgressRing.nodeId`(B)、`claimingNodes` 集合 + `badgeSlotBuffer` 复用缓冲。
- `CreateProgressRing`：写入 `ring.nodeId`(B)。
- `HandleRoundApplied`：开头 `RebuildClaimingNodes()`(B，必须在两个 Refresh 之前)。
- `LayoutStationBadgeRow` 重写：两趟选图标(盖章优先→库存补满封顶)、领取中整行收起、"+K"角标、障碍始终 1 槽、按 `badgeSlotBuffer` 统一居中排。
- 新增 `TryLiveResourceIcon` / `EnsureOverflowChip`(懒建角标) / `RebuildClaimingNodes`。

`Assets/LycheeReplayDemo/LycheeReplayPlayer.cs`
- `ShouldShowWorldPulse`：删 `RESOURCE_CLAIM`(B)，保留 `RESOURCE_USE`(用冰鉴/马有独立车队演出)。

## 别改坏（回归红线）
- **别把 `LayoutStationBadgeRow` 改回"全部图标全量常显"**——那正是"太多"的根因。
- 封顶数 = `MaxResourceIconsShown` 一处常量；间距 = `StationBadgeSlotSpacing`；要调只动这两处。
- `resultMarked` 图标必须优先显示（刚领到的结果盖章别被封顶藏了）。
- `RebuildClaimingNodes()` 必须在 `RefreshResourceMarkers/RefreshObstacleBadges` 之前调，否则收起判断用的是上一帧数据。
- 障碍徽章**不随领取收起**（节点固有信息）。
