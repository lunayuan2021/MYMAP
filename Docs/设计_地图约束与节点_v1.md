## 0. 一句话目标
**基底是一张平板（Y=0）**，全图只允许三种"显式起伏"：①河道下挖（−）②山脊微抬（+）③其余（官道/支路/节点广场）一律贴 0。除此之外任何高度差都视为"杂层"，要消掉。**河道下挖与山脊抬起都必须是「同一张基底地形」的局部变形（一层地形被压低 / 抬高），绝不叠独立的河床网格或山体网格成多层**——路面贴着这张面起伏，水面是槽里唯一一张薄水面（统一高度）。建筑节点的高度由它"汇聚了什么"决定。（注：§7 背景山脉是负空间的装饰 prop，与这张玩法地形层无关，不算"多层"。）

### 0.1 通用化（硬性要求）—— 这台生成器要批量产多张图
- 所有约束**配置驱动、不写死 map1 的具体布局**：按每条边的 `routeType`、每个节点的「度 + 入射路型集合」动态判定，**不依赖特定 edgeId/nodeId**。
- 数值集中为命名常量（沿用现有 `RoadWidth`/`CarveDepth`… 风格），新约束同样进常量区便于调。
- **确定性**：散布/抬升一律用坐标哈希，**禁无种子 Random**（可复现、跨图稳定）。
- **边界自适应**：散布范围 / 边界环 / 盆地由 config 节点坐标包围盒推导，**不写死尺寸**。
- **缺型容错**：某图缺某路型 / 无水路 / 无山路 时不报错、不留空容器。
- 每条约束须在 map1、map2（26/15 vs 21/15）及未来新图上**自动成立**。

### 0.2 素材复用政策（硬性要求）
- **只用工程内已有 asset 包的素材/贴图/模型**（ALP_Assets、Pure Poly、IgniteCoders、URP Tree、现有 `M_*`/`Ground*` 等）。
- **不**用 AssetGeneration 生成新低面模型/贴图；需要新外观时优先**改已有材质参数**或**换已有贴图**。
- 背景山川树石复用 `mountain_terrain_02` / `rock_set_01~04` / `URP_Tree_1~3`；具体「视觉需求 → 已有素材」映射见 **§9 资产表**（审计后补）。

## 3. 建筑节点（站点）分级 — 按"汇聚什么"定高度与形态

> 现有：`BuildBusyJunctions` 找出汇聚 >2 条路/河的"忙站"，`CreateRibbonMesh` 在忙站 3.5m 内把路面末端收窄到一半（line 972/1003）。这套保留并扩展。

| 级 | 触发条件 | 高度 | 形态设计 |
|---|---|---|---|
| **N0 普通站点** | 度 1~2，单一路型 | Y=0 小台（AnchorLift 0.018）| 现状，不变 |
| **N1 忙站** | >2 条路/河汇聚 | **+0.10 夯土小广场** | 路面末端收窄（已有）+ 中央抬一块集散台，像驿镇集散地 |
| **N2 汇水节点** | ≥2 条水路，或水陆交汇 | 水面 = §2 统一水面高度 | **一个统一水池**替换现在乱叠的 pool/patch，石砌驳岸一圈 |
| **N3【我的设计】山口/关隘** | ≥2 条山路汇聚 | **山脊 crest + 额外 +0.35（全图制高点）** | 夯土/石砌台基，像扼守山道的关隘；周边山脊向它收拢抬高 |
| **N4【我的设计】临水驿站** | 站点邻接水路 | 站台抬到水面上 +0.15 | 半边在岸半边出挑水上：**码头木栈 + 乌篷船 + 拴船桩**（现有 `WaterStation_Split`：House_OnLand/Dock_AboveWater/Boat_OnWater，增强木栈与桩）|

| **N6【我的设计】山路↔官道 过渡** | 山路接官道的节点 | 一段缓坡把 crest 高度渐降回 0 | **避免硬台阶**：过渡段 ~3~4m 把山脊高度 SmoothStep 回平地 |

设计意图：让"节点是什么"一眼读得出——制高点必是山口、最低点必是汇水、最大最平的是官道城镇。高度本身成为玩法语言。

## 4. 防"对不上 / 台阶" 的横截面铁律
- 任何动地形处（挖河 / 抬山脊 / 节点抬升），**地形几何 + heightSamples + 路面网格 + 运行时 pathPoints 四者同源 Y**，否则路面入地、小队悬空、船浮空。
- 抬升/下挖一律用 `SmoothStep` 渐变收口，**端点不顶站点、不留垂直壁**。
- 收窄沿用 `NearBusyJunction(p, 3.5)` 半收逻辑。
