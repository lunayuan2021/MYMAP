## 0. 一句话目标
把生成器的**基底地形从"随机起伏"改成"平面 Y=0"**，地形起伏只由**显式的路型约束**产生：**河道下挖、山路抬山脊、官道/支路保持平整**。这能根治"黑路 / 对不上 / 露草 / 层次乱"——它们的共同根因就是随机地形。

---

## 1. 为什么做这个 pivot（用户的关键决策，已确认）
随机起伏地形导致：
- **黑路**：路跟随机地形沉进天然谷地深沟、被挡光成纯黑（见 §5 已排查清单）。平面上路永远受光。
- **"很多地方对不上"**：随机地形 + 任意折线路，路面/河床/站点各自采样随机高度→错位。平面基底 Y=0 天然对齐。
- **露草/层次乱**：只有显式改造处才该有起伏。
平面基底 + 按路型约束，正是"玩法棋盘 + 程序生成"该有的架构，**每出新图自动干净、零人工手调**（这是用户最在意的诉求）。

## 2. 下一轮要做的（实现方案，按步骤）
**基准用 Y=0（已和用户确认倾向，落地前再问一句即可）。**

| 步 | 内容 | 风险 | 现状 |
|---|---|---|---|
| **1. 压平基底** | 地形 mesh 顶点 + `MapElevationData.heightSamples` + `ctx.terrainSurface` 采样器统一压到 Y=0；splat 顶点色保留 | 中（动地形+高度场+站点高度） | **要新写**。单独这步就能让黑路消失，最立竿见影，建议先做 |
| **2. 山路抬山脊** | 沿 Mountain 路折线把地形抬起（和 CarveRivers 挖河**对称**）+ 砂石/岩 splat | 中 | **要新写**（当前**没有**任何山路抬起逻辑，山路只是平地上画了条路） |
| **3. 河道下挖** | 现成 `CarveRivers`，在平面上挖更干净 | 低 | **现成**，复用 |
| **4. 官道/支路** | 不动地形，平铺在 Y=0 | 低 | 自动（不再有黑沟） |
| **5. 站点** | 落在平面 + 各自小台（看 `LiftWaterStationsAboveWater` 水驿/码头抬升） | 低 | 站点位置当前用 `elevation.SampleWorldHeight + AnchorLift`，压平后自然到 0 |
| **6. 运行时复验** | 小队走路读 `heightSamples`、划船读水面/pathPoints——压平后必须重验"不悬空/不入地" | 高 | 每步截图 + 数据兜 |

**实现要点 / 落点**：
- 压平最稳的位置：在 `BuildTerrainSurface`(grep `static void BuildTerrainSurface`) 收集地形之后、边循环建路 + `CarveRivers` 之前，新增 `FlattenBaseTerrain(ctx)`：克隆每个 `ctx.terrainFilters` 的 mesh、把所有顶点 `verts[i].y = 0`（本地空间注意 transform）、`RecalculateNormals`、`SaveMesh` 重赋；同步把 `ctx.elevation.heightSamples` 全置 0；然后**重建采样器** `BuildTerrainSurface(ctx)` 一次（让 `ctx.terrainSurface` = 平面）。这样后续建路 `ConformY`(grep `static float ConformY`) 取到的就是平面、CarveRivers 在平面上挖。
- 山路抬起：仿 `CarveRivers`/`TryCarveTargetY`(grep 之) 写一个 `RaiseMountains(mountainEdges,...)` + `TryRaiseRidgeY`：沿山路中心线距离 d<半宽时抬高（中心最高、向外渐降回 0），U 形倒过来；同步抬 `heightSamples`；splat 把山脊顶点染岩/砂（G 通道，见 §4 splat 约定）。注意端点收口别顶起站点。
- **四处同 delta 铁律**（复用之前的经验）：任何动地形的改动，**地形 mesh / heightSamples / 贴该地形的路面网格 / pathPoints 必须同源 Y**，否则路面入地 + 小队悬空。压平是统一到 0，最简单；山路抬起要确保山路路面也随地形抬（路面 ConformY 会自动跟，只要采样器/heightSamples 已抬）。

## 3. 怎么操作（生成器 + MCP 实操，避坑）
- **重生成 map1**：MCP `Unity_RunCommand` 调 `LycheeMapLayoutGenerator_20260613.RebuildOfficialMap1();`（输出场景 `Map_medium`）。
- **重生成 map2**：MCP 调 `LycheeMapLayoutGenerator_20260613.ApplyLayout("Assets/StreamingAssets/Tournament/map2_config.json", "Assets/Scenes/GeneratedMaps/Map_map2.unity", "map2", "Tournament/map2.txt", "Assets/LycheeMap15/Configs/Maps/ui_map_config_unity_full_coverage_v2.json");`
- **改了 .cs 后必须重编**：MCP 调 `AssetDatabase.ImportAsset("Assets/LycheeReplayDemo/Editor/LycheeMapLayoutGenerator_20260613.cs", ImportAssetOptions.ForceUpdate);` → `isCompiling=True` 即触发。**`AssetDatabase.Refresh()` 单独不触发重编**。
- **MCP 桥频繁掉**（域重载后）：报 "Unity not detected" / "Connection closed" → `open_application com.unity3d.UnityEditor5.x` 把编辑器拉到前台、等 `pgrep -f "RelayApp~/relay"` 出 pid，再重试。等编译可 `sleep 8`。
- **改材质**：用 MCP 改**已有**材质（`mat.SetColor/SetTexture/SetFloat` + `AssetDatabase.SaveAssets()`）OK；**新建材质/DeleteAsset/CreateAsset 会报 "User interactions are not supported"**（Validation Level=standard），别在 MCP 里建材质。
- **截图**：`Unity_Camera_Capture`；看材质细节时 `RenderSettings.fog=false`（重跑会恢复 fog=on）；框场景用 `SceneView.lastActiveSceneView.LookAt(...)`。
- **MCP 动态脚本限制**：不允许 `System.Reflection`、不允许 `HashSet` 的 `string.Join`（动态程序集缺 System.dll 引用，用 `List`+`Contains` 替代）。

## 4. 地形 splat 着色约定（动地形时必须配套改色，否则露草/对不上）
- 地形外观由**烘进顶点色的权重**决定（`LycheeTerrainSplat.shader`，已加 triplanar 防陡面拉花）：**R=路缘土 G=岩/砂(Layer2，现 PP_Pebbles_Light_Brown) B=变化草，主草=1−R−G−B，A=噪声**。
- **挖河/抬山脊只改几何不改色 → 露草**。CarveRivers 里已有"挖到的顶点强制 G=1 染砂"（grep `RiverSandSplatWeight`）。山路抬起同理要把山脊顶点染岩/砂。
- 详见项目记忆 `terrain-splat-carve-decoupling`。

## 5. 黑路问题（本轮没根治，但平面基底会顺带解决）
纯黑路**已系统排除**：材质亮（`_BaseColor`≈1.36）、法线朝上(0.98)、SSAO 关了没变(`PC_Renderer.asset` 里 SSAO Intensity 0.4，已确认不是它)、平行光阴影强度 0.55 没变、环境光 Trilight 0.73 不低。亮材质+正常法线却纯黑在标准光照下不该发生——**根因是路面坐在又深又窄的随机地形沟里被几何挡光**。**平面基底后路在 Y=0 平面、不再有沟 → 黑路自动消失**（这也是先做压平的最大理由）。若平面后仍有残黑，再单查烘焙 GI/光照探针。
